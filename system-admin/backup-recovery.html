Recovery Instructions

  1. Where your data lives: The primary database is MongoDB Atlas. Free-tier clusters generally do not include automatic backups, so do not rely on the host alone—download an export regularly.
  2. Manual Export: Click Backup (.json) to download a complete snapshot for recovery, or Excel report (.xlsx) for a readable workbook (one sheet each for residents, requests, appointments and more; for reports only, not for restoring). It contains accounts, requests, appointments, announcements, settings and the audit trail. It does not contain passwords, login sessions, or uploaded files (ID photos, attachments, avatars).
  3. Secure Storage: The file holds residents’ personal information. Keep it in a password-protected drive or encrypted storage, share it only with authorized people, and delete old copies you no longer need (Data Privacy Act of 2012, RA 10173).
  4. Restoring records: The export is meant for safekeeping, review and recovering records. It uses MongoDB Extended JSON, so ids and dates are preserved. To restore from it, contact the lead developer and provide the latest file; check that it ends with "complete": true, which means the download was not cut off.
  5. Full disaster recovery: Because the export leaves out passwords and uploaded files, use a database dump for a complete recovery: mongodump --uri="<MONGODB_URI>" --out=backup-folder to save, and mongorestore --uri="<MONGODB_URI>" backup-folder to restore. Treat dumps with the same care as exports, since they include password hashes.
Recommendation: Export weekly, or right after large batches of registrations or approvals, and keep at least the last few copies. Each download is recorded in the Audit Logs as “Data Export”.
